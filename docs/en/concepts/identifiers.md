# Identity and session identifiers

[简体中文](../../zh-CN/concepts/identifiers.md) | [Documentation](../README.md)

A session and an execution are different identities. A business session can contain many turns, and retrying one message can create several execution attempts.

| Identifier                        | Supplied / generated by                                                                    | Stored by                                                   | Purpose and lifetime                                                                                   |
| --------------------------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| bot_id                            | Platform / host configuration                                                              | Gateway definition or CLI configuration                     | Bot identity scoped by API address; a display name is not authorization                                |
| conversationId / messageId        | Platform incoming message                                                                  | Transport and bounded occurrence records                    | Conversation location and deduplication, not execution cancellation                                    |
| sessionId                         | Gateway for a logical session; direct client callers may provide it or let it be generated | Session binding                                             | Correlates turns; the next ordinary input establishes a new session after reset                        |
| generation                        | Gateway reset/new control                                                                  | Session binding                                             | Separates logical sessions and rejects stale updates                                                   |
| invocationId                      | Gateway per attempt; direct client callers may provide it or let it be generated           | Active task and owning client registry                      | Identifies one invocation; target of interrupt                                                         |
| runId                             | Gateway/caller or client                                                                   | Execution records and log correlation                       | Runtime execution tracing, not a Provider session                                                      |
| providerSession                   | Adapter from Provider results                                                              | Gateway session binding                                     | Native continuation information; never guessed from business sessionId                                 |
| sessionGeneration / providerEpoch | Gateway orchestration; both currently use the session generation                           | Invocation drafts, protocol metadata, and execution records | Logical-session / Provider-binding generations for correlation and isolation, not cancellation targets |
| kernel_instance_id                | Kernel on startup                                                                          | Client execution references                                 | Prevents references crossing Kernel incarnations                                                       |
| stream_id / seq                   | Kernel event stream                                                                        | Client observation cursor                                   | Resume observation and deduplicate events, not resubmit work                                           |

For example, turns A and B in session S have different invocationIds. Interrupting A cannot use sessionId=S because it does not identify the turn. Gateway sends A's invocationId through its owning client. Native Provider turn IDs remain internal to the Adapter; applications do not implement each Provider's cancellation protocol.

Client handles expose invocationId/runId/sessionId before first consumption. Accepted interruption does not prove Provider exit: continue observing the original execution to a terminal and check cleanup. See [Session management](../guides/sessions.md).
