## 承重合同与方案

- configure 按规范化 API 地址与 bot_id 联合身份更新，其他身份不变；只可从同一身份保留凭据。新 API 上配置已有同名 Bot 时缺新凭据明确拒绝；首次无凭据配置仍是合法的离线准备。
- 无效表单是单事件的永久拒绝，诊断、ACK、推进读取位置；传输/控制未知和 ACK 失败仍保留重试，不自动重放已执行控制。未知或未授权事件继续只推进读取位置，遵守现有跨领域事件合同。
- REST 默认不跟随重定向，包括原直连 fetch；不把 fetch 跨源自动剥离鉴权误称为已泄露 token。
- Windows 所有任务变更须确认当前用户身份，异主或身份未知拒绝；安装覆盖前也须检查。不增加系统权限或操作实际用户服务。
- final 输出单独限制为 128 条、合计 1 MiB UTF-8；超限显式报错并进入既有取消/结果未知路径，不能静默截断为成功或自动上传不完整产物。

## 排除与范围外

不修改 Manager 工厂后关闭检查、默认可选 artifact roots、独立 WS 服务域和 systemd 单路径空格语义。这些行为由代码守卫或明文合同支持。不是所有外部 finding 都是本 PR 新回归；Windows 与 final 上限属于迁移前已存在的缺口。
